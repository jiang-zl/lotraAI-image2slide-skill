# Current-task repair workflow

Use the current model to understand the unchanged original and decide semantic
ambiguity. Diagnostic commands order and measure work. Finite advancement uses
existing guarded executors with already frozen source facts or registered
plans. Neither route invents observations, accepts a result or bypasses any
original child, saved native descendant or table cell.

## Agenda before scattered repair

```
PYTHON SKILL/scripts/run_lotra.py --project PROJECT workflow-control TASK plan --out TASK/scratch/Agenda.json
PYTHON SKILL/scripts/packet_detail.py TASK scratch/Agenda.json HASH groups --purpose repair_agenda
PYTHON SKILL/scripts/packet_detail.py TASK scratch/Agenda.json HASH records --offset 0 --limit 16 --purpose located_failures
```

The current registered whole report must match the actual original, PPTX,
preview, implementation and decision basis. Stale reports are named explicitly
and cannot supply failure facts for a new repair. Without a current whole
report, follow the current packet; do not run a speculative whole audit merely
to obtain an agenda. Current `next`/`submit` contracts remain authoritative.

The retained agenda includes every failed gate and every explicitly located
failure record, with selectors into its full immutable program report. Follow
all continuations. Parent and child failures can both appear; grouping is not
independent coverage or a quality vote. A status does not infer a semantic
cause. The model reads the exact located contract and original/actual views.

Order work by its current dependencies: measurement validity; original facts; host/native capability;
typography/content/math; geometry/relations/cells; anatomy/fidelity/material;
current-file evidence binding; and final global quality. The dependency summary
reports actual changes, affected counts and the reason for a complete scope.
It neither shrinks the scope nor relabels an unknown dependency as known.

Within a dependency phase, located records with the same explicit owner have a
current hash-bound `resource_group`. Use it to prepare adjacent permitted actions
and reuse their pixels/XML/PDF under the batch scope. Reports can mutate state;
grouping does not prove independence or authorize automatic reordering. For
resource lifetimes, early pixel hits and exact sampling rules, read
[resource locality](resource-locality.md) only when needed.

## Measurement diagnosis and finite advancement

`native_owners`, `quality_unit` and `obligation_id` are distinct. A check's
arbitrary ID cannot become an object's write authority. Nested span/scale
failures retain their explicit parent's owner, while child owners override it.
Each failure remains in the agenda; grouping never drops a parent or child.

```
PYTHON SKILL/scripts/run_lotra.py --project PROJECT workflow-control TASK advance --request TASK/scratch/Advance.json --out TASK/scratch/Advance-result.json
```

An optional request is `{source_hash:"CURRENT_ORIGINAL_SHA256",max_actions:4}`,
with a finite bound of 1..8. The program follows the real `next` contract and
can execute source-bound AST/OMML content corrections for up to 16 owners in
one native transaction, or an agent's already registered recursive plan.
Typographic-only ambiguity and graphical-carrier conversion need their normal
explicit decisions. Pending font binding, font delivery, user edits and saved
host-render work take precedence over an older rendered candidate. These
boundaries return their current packet. No later plan is silently rebased.
Completion of an action means current rendering and complete checks remain
required; acceptance still performs an independent fresh whole audit.

The same immutable current report may route work repeatedly while original,
candidate, preview, render, code and decision basis all match. Changed bytes or
decisions force current measurement. This reuse cannot supply final acceptance.

HD edge crossings must be bracketed, finite, ordered and inside the probe.
An invalid crossing supplies no width or gain. `icon-clarity probe-review`
locates the original/current failure and returns unchanged neighbor context.
When an ORIGINAL probe is invalid, `icon-clarity rebind-probes` accepts only
that diagnosed probe's reobservation, retaining all IDs, every valid probe,
anatomy, thresholds, materials, comparators and child checks. Its replacements
must measure valid source crossings before saving the new contract. Missing
candidate contrast or candidate displacement does not authorize moving a
valid original probe. Diagnose actual sampling/capture or use the existing
bounded native repair, then run the complete current audit.

Fixed-frame colour distribution uses eight bins per RGB axis with continuous
trilinear membership. `raw_hard_color_histogram_tv` retains the old discontinuous
diagnostic. The frozen frame, SSIM/boundary/content/material and declared bounds
remain separate; no candidate matching, registration or relaxed target is used.

## Early native parsing diagnosis

```
PYTHON SKILL/scripts/run_lotra.py --project PROJECT workflow-control TASK preflight --out TASK/scratch/Native-preflight.json
```

Use the registered readiness probes before construction. Once a representative
current native candidate exists, inspect its preflight before deep parameter
search. It enumerates active native descendants on every saved slide and every
saved table cell, checks the first diagram slide's existing geometry decoder,
and records missing transforms/font references or unsupported geometry. Extra
slides remain explicitly unmeasured by that decoder. Never substitute shape
envelopes for actual painted geometry.

This is a parsing/inventory diagnosis, not an actual Office behavior or quality
test. Full fonts, genuine Office Math, table semantics, HD re-identification,
1x/2x/4x actual vector-PDF fidelity/material, actual editing/save/reopen and all
local/global predicates still require their normal current evidence. A decoded
path is not a faithful source reconstruction. No source detail is inferred.

## Fully prevalidated finite batches

```
PYTHON SKILL/scripts/run_lotra.py --project PROJECT batch TASK --request TASK/scratch/Batch.json --out TASK/scratch/Batch-result.json
```

Example request (replace TASK and hashes with the registered current facts):

```json
{
  "source_hash": "CURRENT_ORIGINAL_SHA256",
  "operations": [
    {"id": "native", "argv": ["workflow-control", "TASK", "preflight", "--out", "TASK/scratch/Native-new.json"]},
    {"id": "agenda", "argv": ["workflow-control", "TASK", "plan", "--out", "TASK/scratch/Agenda-new.json"]}
  ]
}
```

Programs validate the whole finite array before invoking the first action:
public parser syntax, allowed operation, same task, portable distinct IDs,
earlier distinct dependencies, existing hash-frozen inputs, and distinct fresh
scratch outputs. Unknown/forward/cyclic dependencies or invalid later rows
reject the complete batch before task actions. There are at most 32 operations
per invocation; this is a transport limit and never an exit or coverage budget.

Every action retains its existing validator, writer lock, exact source/plan
binding, protected properties, independent object best and local rollback.
The batch does not execute arbitrary code/XML, grant additional edit scope,
rewrite evidence hashes, or parallelize dependent state mutations. Actual
outputs and stdout/stderr survive both success and failure.

`EXECUTED` means the command returned successfully. The report's `domain_status`
and optional `domain_passed` are separate. A `depends_on` only requires execution;
add `requires_status:{"earlier_id":"EXACT_EXPECTED_STATUS"}` when a consumer
requires a domain result. Each scientific executor must still independently
validate its prerequisites and current hashes. Batch success is not acceptance.

Existing finite routes include grouped rule plans and protected text/layout/
structure repairs, alongside independent reports and observations. Consult
`scripts/core/batch_plan.py` for the exact allowlist and each current packet's
action reference for its schema. Prefer a supported multi-target plan for
same-baseline changes. Once a mutation changes the candidate, prepare a later
mutating request against the actual new packet. Prewritten requests bound to
the old baseline intentionally fail; the batch never silently rebases them.

After a failed branch, inspect its located cause and select a changed,
evidence-supported action. Keep v1.27's identical-rejection and ineffective-
branch controls. Pruning a branch leaves the obligation pending. Build each
object's measured best, then perform complete current native/source/cell
reconciliation, independent final facts, all local/global gates and the normal
accepted export. A temporary PDF survives all consumers, then is released.

## Cost diagnosis without invented savings

```
PYTHON SKILL/scripts/run_lotra.py --project PROJECT workflow-control TASK profile --out TASK/scratch/Profile.json
```

New command spans record parent IDs, actual start/end, exception/return status,
inclusive time and exclusive time after nested command durations. Existing
runtime and legacy command ledgers are inclusive and must not be added again.
Profile pages are current-task only; read all necessary continuations.

Only recorded program intervals are measured. Model reasoning, host delays,
interruptions and whole-task elapsed are unknown unless separately supplied.
Missing spans remain missing. A profile is not a quality gate or service usage.
Actual service tokens use `context-usage`; characters, bytes, cache hits and
local timing cannot establish token savings or end-to-end reconstruction gains.
