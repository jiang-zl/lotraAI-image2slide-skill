# Spatial workflow closure in v1.35.2

New contracts use `workflow_version: 1.35.2`, `design_revision: 8`. This patch
retains `source-features-1.35.1` and `spatial-1.35.1`; no duplicate observation
schema is introduced. Read workflow-v1351.md for typed subjects, complete
footprints, canonical constructors and spatial parameter bindings, together
with the retained v1.34 native-priority rules. Bound originals, observations,
quality bounds, independent bests and user locks remain source-owned. An old
workflow changes version only through an explicit `migrate_spatial: true` bind.

## Construction, fitting and layout

Prefer native presets, compact composites/shared faces and bounded native paths.
Native shapes, fills, outlines, text and genuine Office Math remain editable.
Initial construction and revisions use the existing common compiler and journal.
The model supplies source meaning and bounded parameters; programs compile,
fit, save and measure. No additional model/provider or runtime resource is needed.

Spatial layout uses the same frozen constructors and parameter vector as fitting.
Without a committed fit it uses the frozen initial values. With a committed fit,
programs verify its source/implementation/measurement basis, recompile its bounded
parameters from the original contract, and compare the current saved native body
and projected frames. Never substitute the candidate's bbox as a source target,
nor compare a valid fitted result only with its initial bbox. All original anchor,
complete-footprint, relation and actual-render gates still apply.

## Native writes and ordered repairs

The existing field grants and native transaction are the common write authority.
Ordinary edits, numerical commits and rollback use actual semantic field changes;
opaque instance/reprojection operations also preflight their complete owner scope.
A waiting/saved phase or whole-owner replacement cannot bypass active field grants.
Successful authorized saves journal the phase and consume its grants, including
numerical saves. Recovery uses that retained transaction, never a fresh write.
Finish a retained source-apply plan before another mutation.

Derive geometry phases from the changed owner and measured anchors/footprints,
including explicitly shared constructor parts. A component's unrelated geometry
does not set a group's phase: a real group transform uses its actual descendant
anchors and footprints. Geometry outside that actual native subtree or resource
does not inherit another owner's earliest failure phase. Material/text and painter
order remain separate. Before later grants activate, remeasure all earlier
obligations, including phases omitted from the submitted field plan. If these
remain unmet, retain the best and return a focused source decision for replanning.
Normal packets select an operation; submit that operation or a focused source/
measurement decision, rather than changing the write route. Active phased repair
packets use scoped edits; automatic fitting does not skip their phase sequence.

## Failure decisions and acceptance

Qualification, layout and final-repair measurement failures persist a hash-bound
decision and current checks in the ordinary ledger. Invalid measurements go to
measurement diagnosis before drawing. The next packet permits the corresponding
source/measurement decision and a validated rebind, instead of repeating a failed
qualification or repair-only packet. Rebinding keeps the prior best and requires
current native rechecks. Previous contracts/ledgers retain superseded repair
plans; current layout/visual checks create a replacement plan only for remaining
failures, rather than requiring a no-op edit for an obsolete failure list.

Pending shared-frame or measurement decisions, observation rebinds, source-apply
plans and incomplete repair schedules block normal advance and final acceptance.
The same readiness predicate governs visual review, audit and accept; calling a
later entry directly cannot clear these obligations. One deferred font review,
current whole visual evidence and fresh saved-native spatial checks remain required.
Work packets reference this file for 1.35.2 and the matching file for older policies.

## Measurement boundaries

Before anchor or logical-frame extraction, inspect actual shape, text-body and
ancestor 3D settings. Unsupported effects return measurement decisions even for
native_text_frame; a 2D text box does not certify its 3D projected geometry.
Prefer editable projected native surfaces when no qualified extractor exists.

Placement signatures use actual world transforms. Changes to absolute XML sequence
indices do not invalidate unchanged sibling anatomy. Declared painter/occlusion
relations separately track changes in the relevant owners' relative paint order.

Visible faces/edges must remain in one finite projective chart. Validate homogeneous
denominators over their vertices and over bounded planar curve control hulls before
discarding homogeneous coordinates. A horizon crossing or unresolved bound returns
a source/representation decision, never a finite straight substitute.

This release is implemented and statically reviewed only. Tests, syntax/import/CLI
checks, reconstruction, rendering and Office behavior runs were not executed at the
user's request. Packaging and source identity checks do not accept user artwork.
Runtime binaries and resources remain independently versioned and unchanged.
