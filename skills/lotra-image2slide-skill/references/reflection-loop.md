Use [the visual agent loop](visual-agent-loop.md) as the default controller. It connects actual result views, open-vocabulary findings, bounded repairs, cumulative freezing and explicit delivery/non-delivery exits. This document remains a method library. # Observe, reflect, repair and retain useful knowledge

The host interprets the reference; deterministic tools build, bind evidence and compute measurements. This loop applies to the current user task. It is not permission to run every example or spend an unlimited budget. User scope and resource changes take effect immediately; preserve already useful work.

## 1. Establish independent observations

View the whole source once, then enlarge uncertain regions. Record source identity, pixel dimensions, text, equation structure, object inventory, directed relations, containment, occlusion and requested edits. Separate observed facts, inferred hidden illustration and unresolved scientific content. Use `source-analysis.json`; the candidate's own shape inventory cannot prove that the source was fully covered.

For each object ask: what is it, which natural parts are visible, which parts overlap, what must remain editable, and what evidence justifies stopping decomposition? A large shape count, descriptive group names, or a crop are not answers. A photo remains a photo; do not fabricate internal scientific anatomy or data.

## 2. Make a small work order

Use `compact-order` for the target, direct children, parent, incident relations and one-hop neighbors. Retrieve only a few compatible recipes. Carry source crops, immutable identifiers, required operations and the concrete defect; do not resend the entire Scene, all example cards or long histories on every iteration.

Classify the defect before editing:

| Observation | Likely cause | Smallest useful action | Necessary recheck |
|---|---|---|---|
| A separated icon contains fragments or a foreground imprint | Visible crop was mistaken for a complete object | Recover a full prototype or complete the hidden region; retain separate visible/inferred masks | Standalone asset, original overlap and exported component |
| Parts move together but cannot be edited meaningfully | Traced fragments were grouped without natural structure | Revisit semantic parts and stage a structural change | Children, parent, edit operations and ownership |
| Correct words have incorrect visual weight or spacing | Wrong font, fallback, size or text box layout | Compare a small supported font/layout candidate set | Actual font/render, full text object and neighbors |
| All nodes exist but a link is missing or reversed | Geometry was checked without source relation coverage | Restore the source-grounded endpoints and direction | Entire connection corridor, incident nodes and topology |
| A label is correct but its dot/bracket is misplaced | Generic placement ignored its real anchor | Repair the anchor/leader relationship | Complete annotation plus the referred object |
| Local similarity improves but the panel becomes worse | Selection ignored context | Reject or revert the local candidate | Parent, overlap neighbors and whole-slide composition |

These diagnoses are hypotheses. State the supporting observation and test the result; do not apply a recipe solely because an object name matches.

## 3. Reflect in a concise, inspectable record

Store observable decisions rather than a long narrative. A review record needs: target ID and source ROI, source/candidate hashes, located defect and severity, evidence, hypothesized cause, chosen action, expected effect, protected contents, affected dependencies, actual result and keep/reject decision. Use existing source/attempt/repair records; an extra prose document is optional.

Example decision: “Rear paper is an L-shaped fragment when moved. Source shows a rectangular paper behind another. Replace only its hidden geometry with a complete native rectangle and matched document motif; preserve observed strokes and front paper. Recheck independent export and the original stack.” This supports an action without claiming recovery of unknowable text.

Prioritize wrong science, omitted content and broken relationships, then unusable components and clear visible errors, then polish. Do not spend repeated whole-page reviews on minor shading while a known endpoint is wrong.

Any observed source feature that vanishes in the saved PPT is a mandatory repair, regardless of size or aggregate similarity. Recheck source and candidate together; restore a missing road/line/shape with one native preset or closed path first. Cut-out backgrounds must pass [visual closure](visual-closure.md) before a raster candidate can be selected. A stitched single exterior fails even if its pieces are individually editable.

## 4. Draw complete, reusable units

Follow [recursive components](recursive-components.md). Use native geometry for labels, equations, relations and promised vector parts. Keep semantic ownership independent of z-order. Overlapping objects need full independent geometry or complete assets; the page composition determines which parts are visible.

Follow [amodal completion](amodal-completion.md) for hidden illustration. Preserve observed pixels through masks and deterministic composition. Record inferred regions and provenance. Use the measured visible error, alpha completeness, recomposition error, seams and an explicit semantic rubric. Unknown hidden ground truth is not reconstruction accuracy. Random candidates may vary non-scientific hidden illustration; never invent numbers, words, formulae, graph edges or experimental imagery.

## 5. Check three distinct scopes

1. **Object alone:** natural-part completeness, independent extraction, source words/formulae, supported edit operations, no burnt-in occluder or unrelated sibling.
2. **Object in context:** original scale/position, contact points, arrow direction, occlusion, neighboring labels, full relation corridors and parent structure.
3. **Whole slide:** independent source omission review, consistent typography and hierarchy, boundaries, panels and the required quality windows. Follow [quality](quality.md) for strict acceptance coverage; generating crops is not reviewing them.

Render the saved PPT and inspect that render. Native XML checks do not prove successful editor use. When a target editor is available, edit a task-owned copy, save, reopen and validate actual changes. Never close another user's presentation. When a capability or review is missing, preserve its unverified state.

Raw SSIM, color error or IoU may help locate regressions. They cannot excuse a lost arrow, incorrect equation or incomplete layer. Compare only matching renderer/font/canvas/mask/checker identities. Avoid reducing all kinds of defects to one uncalibrated number.

## 6. Repair with an explicit invalidation scope

Stage an immutable candidate. Validate the changed object, its old and new occupied regions, ancestors, overlap neighbors, incident relations and exported owners. Perform a whole-slide context glance after recomposition; repeat full measurement only if dependencies or broad layout changed.

Reuse an earlier observation only with recorded proof that its crop bytes and relevant source/object/dependency, render/font and checker identities are unchanged. A file name or “same object” assertion is insufficient. If reuse cannot be proven, leave the observation pending or perform the necessary check. Never alter old receipts to match a new file.

Retain `best_local`, `best_in_scene`, working selection and fully feasible selection separately. A local win with a contextual loss is a rejected candidate. Record helped, neutral, harmful, tradeoff or unmeasured accurately. Hashes bind evidence; they do not make a visual judgment true.

## 7. Stop for a stated reason

Do not force extra rounds after the declared checks pass and no located defect motivates another action. Do not repeat the same unsuccessful change without a new hypothesis. A stalled or budget-limited attempt preserves its best working result and unresolved list; it is not ACCEPTED. Only complete applicable evidence and valid calibrated gates can establish that state.

When the user limits the budget or asks to stop broader experiments, stop those experiments, retain reproducible state and deliver within the revised scope. Distinguish “runtime released,” “candidate useful for review,” “observed improvements” and “fully accepted drawing.” Do not claim absolute optimality or an untested model's success rate.

## 8. Learn from real outcomes

Follow [local knowledge](knowledge-library.md). Capture a reusable recipe only when it changed an actual drawing decision. Store applicable views/parts, parameters, provenance, edits, failures and limits. Require a positive case, meaningful rejected case and independent reuse before promotion. Quarantine harmful entries and retain a revocation path. Private task images stay local; they never enter a distributed package automatically.

Record context characters/crop counts/calls and actual tokens if the host exposes them. Character counts are not token billing. Smaller work orders and explicit choices reduce task complexity; cross-model effectiveness remains unverified until actually tested.
