# Executable recursive components

Keep source semantics, requested edits, rendering slots and measurement windows separate. Preserve source node IDs and facts when changing the representation. Refine observations explicitly before adding new parts; do not derive source coverage from the candidate inventory.

1. Load one component and its parent with `compact-order ANALYSIS OBJECT --out ORDER.json`. The work order includes direct children, their incident relations, one-hop neighboring nodes, and the source evidence for those relations, neighbors and parent. It does not recursively load neighboring subtrees. The character limit includes the accounting envelope; if it is exceeded, split the work instead of silently truncating evidence.
2. Choose useful natural parts and a native or explicitly allowed hybrid representation. Use `instantiate-recipe REQUEST --out PARTS.json` only after the class, view, part count and parameters match observations. Available initial geometry: `wireless_signal`, `model_document`, `server_rack`; these are priors with independently editable instances.
3. For a structural change, call `restructure SCENE ANALYSIS REQUEST NEW_ANALYSIS --resources WORK --out WORK/candidates/ID`. The request binds both input hashes, root ID, authorized subtree IDs, reason, source evidence and full replacement objects. Actions: split, merge, replace_representation, complete_occlusion. Scientific endpoints outside the subtree must retain their identities. A changed child endpoint needs a separately authorized mapping.
4. Build the staged file using `build WORK/candidates/ID/scene.json --resources WORK --out WORK/candidates/ID/Candidate.pptx`. Then render and verify changed parts, old/new neighbors, parents, science relations and exported components. A structurally valid candidate is not accepted.
5. Use the existing iteration registry for measured candidate selection. Local, contextual and fully feasible best remain separate. Keep rejected attempts with their reason; restore the selected scene pointer when a candidate harms the parent.

Drawing order is not semantic ownership. `inventory-pptx FILE --out inventory.json` records actual saved IDs and transforms. An explicit owner manifest can select multiple native fragments from different layers. `export-owned-components FILE OWNERS --out Components` preserves their ancestor transforms, excludes siblings and records detached external connector attachments. Inspect the exported file in PowerPoint. Unsupported transforms during native replacement cause a specific error, not silent geometry loss.

Use [original-region recursion](source-recursion.md) for the mandatory program-owned frontier and typed stop proof. Stop semantic decomposition at a verified task-relative unit or justified editing boundary; required drawing parts and saved-content checks remain independent. Empty evidence, arbitrary maximum depth, selecting a bitmap, or a large shape count cannot justify stopping. Unresolved observations and resource limits remain incomplete states.
