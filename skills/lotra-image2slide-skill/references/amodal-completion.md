## v1.0.3 policy boundary

Choose the intended appearance policy first; see [visual-agent-loop.md](visual-agent-loop.md). `source_faithful` and user-approved preservation keep their visible-pixel contract. For a blurry illustrative asset requiring `semantic_hd_replace`, the entire clear complete layer may be generated/reconstructed, including formerly visible pixels; do not route it through a visible-pixels-must-match gate. Preserve source meaning, composition and all approved content outside the target. A generated full subject still needs independent-layer observation and must not duplicate another instance or invent scientific evidence.

# Full reusable objects behind occlusion

For each occluded owner, retain an independent full component plus source-visible and inferred areas. A rectangle containing another thumbnail, an L-shaped cutout, or a color trace missing the hidden half does not satisfy independent reuse.

When the task explicitly authorizes redrawing an entire illustrative training-sample card, do not splice a new subject into the hidden half of an old subject: that can produce two heads or a broken body while the composed slide still looks unchanged. `replace-picture-layers` accepts `replacement_mode: "new_illustrative_sample"` with `kind: "illustrative_photo"` for this separate case. It replaces the complete named picture payload while keeping its PPT geometry and all other saved owners, and requires a unique high-resolution asset, semantic instance ID, nonempty category, source-region references, generation tool, reason, and located whole-subject host review. The review must bind `asset_sha256`, `category`, and `semantic_instance_id`, and independently mark `whole_subject_continuity` and `single_subject` PASS with visual evidence. This mode authorizes a visible change inside the card. It does not claim original-pixel preservation, recovery of an unseen original, or a local edit to an already approved slide. Render and inspect the entire page and each separated card before selecting it. Use `complete-asset` instead when already-visible pixels must remain frozen.

Prefer observed same-source recovery, then fitted native geometry or a compatible prototype for icons. For illustrative photos, a semantic donor or an available host image tool may propose unseen content. Random candidate selection is allowed only inside explicitly unobserved, non-scientific areas and is recorded. A donor sharing a category does not prove the same hidden image identity.

When a photo stack repeats the exact same illustrative thumbnail, use `measure-illustrative-diversity LAYERS.json --resources WORK --out REPORT.json` to record exact duplicates, pairwise SSIM and donor lineage. Set `repetition_policy` to `distinct_samples` or `observed_repeat` with `policy_evidence_refs` to source locations. A stack's front card does **not** reveal the hidden rear cards' source subjects. Use a broad common `category` such as `training_samples` when the stack contains potentially different classes; record each card's `source_subject_status` as `observed`, `inferred` or `unresolved`, its `source_evidence_refs`, and a `source_subject_category` only when the source actually identifies it. Record `candidate_subject_category`, `candidate_visual_evidence_refs` and `semantic_instance_id` from the **separated candidate**, not by projecting its content backward onto the source. For distinct samples, attach hash-bound `variant_receipt` and/or `completion_receipt` when generated. A bounded affine/tone transform of one donor is **not** a new semantic instance even when SSIM falls below the near-duplicate threshold. A source-supported repeat is legal, but an unverified claim of repetition or unique identity is not visual evidence. The host must inspect each isolated **whole** object for duplicate subjects, impossible joins and style before promotion. A generated full image pasted into a hidden pocket can make a second horse appear; a supposedly source-aligned donor can also erase a hidden horse head. Both can leave every protected pixel and the recomposed page unchanged. The tool reports semantic status UNVERIFIED until that inspection; no numerical diversity score can promote it.

For a stack of potentially different samples, write an `illustrative-stack-plan-1` request before generating. It lists a source-grounded `repetition_policy`, `policy_evidence_refs`, one entry per card with `layer_id`, hash-bound `completion_contract`, `source_subject_status`, `source_evidence_refs`, an observed `source_subject_category` only when actually visible, and a separately chosen `candidate_subject_category`. Optional donors have a hash-bound full asset, matching category, semantic instance ID, and located whole-subject review with `status: PASS`. Call `plan-independent-photo-layers REQUEST --resources WORK --out WORK/stack-plan.json`. The planner uses each independent whole donor at most once under `distinct_samples`; otherwise it returns `HOST_GENERATE_ONE_FULL_SUBJECT` or `NEEDS_HOST_CATEGORY_DECISION`. The latter is a real stop, not permission to invent source facts. The host brief requires one complete subject, matching viewpoint/style and fixed canvas. Generation is done by an actually available host image tool; the deterministic runtime cannot claim it generated an image.

After `complete-asset`, inspect the separated full card at source size and enlarged. The illustrative-photo semantic review additionally requires `whole_subject_continuity` and `no_extra_subject` with located evidence. This catches a second horse or a missing head even when visible-pixel preservation is perfect. Use `measure-illustrative-diversity --review REVIEW.json` for pairwise instance identity. The review binds ordered asset hashes, `policy_hash = identity({"repetition_policy":...,"policy_evidence_refs":...})`, a real human/host-model reviewer, one card record per index with matching candidate category, `whole_subject_continuity`, `single_subject`, and evidence, plus every pair in index order with `PASS_DISTINCT` or `PASS_OBSERVED_REPEAT` (or FAIL/UNVERIFIED) and evidence. Exact duplicates, identical declared instances, and bounded transforms of the same donor remain failures under `distinct_samples`, regardless of review prose. Review PASS is plausibility of the candidate, never recovery of the unobserved historical pixels.

`generate-illustrative-variant REQUEST.json --resources WORK --out VARIANT.png` makes a deterministic, bounded transform of a verified same-category donor; it deliberately refuses scientific/data images and keeps semantic status UNVERIFIED. This is only a source-derived proposal, not a semantic generator. For opaque, unrotated, later-sibling picture stacks, `freeze-photo-stack-visible-mask BASE.pptx TARGET_ID OCCLUDER_ID... --margin 6 --out VISIBLE.png` freezes the source-pixel exposure plus a conservative renderer sampling margin **before** completing the candidate. If actual rendering changes the composed page outside authorization, reject it; a new attempt needs a separately frozen mask and another render. Inspect the extracted hidden asset and its page context. A zero-duplicate count is one metric, not permission to promote an implausible image.

The `completion-1` contract includes owner, kind, category, method, source, visible_mask, amodal_mask, protected_mask, evidence_refs, reason and hidden_status. Each file reference has a relative path and SHA-256. Masks use the exact component canvas and binary pixels. The amodal mask denotes opaque object interior, excluding uncertain antialias fringe. Visible must be nonempty and contained by amodal; inferred pixels cannot intersect protected science. Generated regions stay `inferred`. The actual image tool/model identity may be `unknown` when unavailable, never guessed.

`complete-asset CONTRACT CANDIDATE_REF --resources WORK --out ASSET.png` preserves observed pixels exactly and inserts the supplied candidate only into the hidden area. It does not itself invoke a generative model or determine semantic masks. Resizing/alignment of a proposed candidate must be explicit and recorded before this command.
For fully opaque RGB source and result, it retains RGB storage; changing to RGBA can alter resampling in a slide renderer even if visible RGB pixel values match.

`measure-completion CONTRACT ASSET --resources WORK --out CHECK.json` reports visible errors, missing opaque support, outside leakage and a seam diagnostic. `--ground-truth REF.json` enables hidden-region error/IoU only for a genuine known original (e.g. synthetic occlusion of a full asset). Otherwise these numbers are null. Never call them reconstruction accuracy without ground truth.

Metric version 1.1 permits an explicit `observed_antialias_mask` resource for already visible fractional-alpha pixels at the outer boundary. It must be a subset of the visible mask, touch the amodal exterior, and correspond to source alpha strictly between 0 and 254. These pixels must remain exactly unchanged. Hidden pixels, interior holes and zero-alpha source pixels cannot use this exemption. This separates a legitimate soft edge from an incomplete component; it does not relax inferred-interior opacity. Comparisons must use the same metric version on every baseline and candidate.

`--review REVIEW.json` adds a bound human/host inspection: category, natural_parts, geometry, view_style and occluder_removed each need PASS/FAIL/UNVERIFIED plus visual evidence. Bind both contract and output hashes. This plausibility review is not a probability or proof of the unseen original. Seam/color/embedding scores cannot replace it.

Inspect at source size and enlarged, separated and recomposed. On transparent assets use light and dark backgrounds. Independently move/duplicate each component, edit native parts or replace/crop photographic layers, save and reopen. Preserve actual observed overlap when recomposing. True experimental/medical images require real same-source recovery; do not generate hidden scientific evidence.
