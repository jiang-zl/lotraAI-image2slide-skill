# Presentation backends and delivery in 1.36.0

Use the recorded project launcher. `presentation-backend --project PROJECT`
qualifies installed programs using a real native fixture with text, native paths
and genuine Office Math. The fixture must export PDF, save PPTX, edit, save and
reopen. Discovery alone is not readiness. Keep backend names and actual scopes
in all receipts; a LibreOffice result never qualifies PowerPoint or WPS.

Selection: explicit command option, then `.lotraAI-build/Presentation-preferences.json`,
then the Windows `.pptx` association among qualified adapters, other qualified
native adapters, then declared LibreOffice. An explicit unavailable backend fails
with its exact missing/failed capability; it does not silently substitute another.
`presentation-backend --project PROJECT --backend powerpoint --save-preferences`
persists a user preference. Supported choices are auto, powerpoint, wps, libreoffice.
Windows uses local PowerPoint COM or WPS KWPP.Application. The macOS PowerPoint
AppleScript adapter and WPS require their own installed host probe; until then
their physical-platform qualification is pending. Never install macros, change
application security settings or quit/kill a shared application. Private helper
timeouts are finite and failure evidence stays with the job.

Keep one source-owned scene/geometry/font/OMML model and use the selected
generator profile. A `p:cxnSp` connector must use preset geometry. An unbound
arbitrary route uses an explicitly unfilled editable `p:sp` native freeform.
Attached endpoints cannot be dropped: choose a valid preset route or return the
located source decision. Schema/ZIP validity is separate from actual Office save.
The final generated package is checked before adoption. Canonical source and
user PPTX are immutable; a backend roundtrip is only an owned validation copy.

LibreOffice is optional when a qualified native backend covers the task, including
Office Math. Its fallback uses private profiles and process-local TEMP/TMP/TMPDIR
on the owned project/output filesystem; never change executable security labels,
ACLs or global environment variables. Actual PDF bytes, page count, all-page
previews and saved native descendants are checked. A PNG or an exit code alone
does not satisfy PDF export. Preserve stage, exception, logs and immutable input
hash on failure. Do not promise that an external application can never fail.

Delivery root: an explicit user directory, then a saved project preference, then
the project root. If no project exists, establish the current harness task
workspace as the project. Never default to global `.codex` storage. User can say
“保存到 D:\slides” or use `export TASK --output-root DIRECTORY`. The component
route is `component-workflow TASK export --output-root DIRECTORY`. Omitting the
root creates `output-slide-YYYY-MM-DD-HHMMSS-mmm` under the project, using the
user's local time and an atomic collision suffix. `--new-export` starts another
delivery; resuming the same candidate/root reuses its reservation. Legacy `--out`
remains an exact new destination for older callers; do not overwrite it.

Private states, manifests, probes, logs and staging audits stay in `.lotraAI-build`.
The chosen output root grants only a new delivery-child boundary; it does not
widen common.safe_path or authorize source/global changes. Stage on the chosen
volume, validate final PPTX and native-save behavior there, verify hashes, then
atomically publish without replacing any existing directory. The final folder
contains only Final_editable.pptx and Report.md. Failure retains a private plan
and owned destination stage; it never emits an accepted receipt. A final
PowerPoint/WPS claim requires that exact final-file hash's own native roundtrip.
LO-only exports record alternative save/reopen and target Office UNVERIFIED.
Whole-image acceptance, current component metrics, native file usability and
host installation are distinct gates. Do not relax original quality thresholds.

WSL exports to mounted Windows volumes use a fixed Windows Directory.Move adapter when renameat2 no-replace is unsupported. The adapter accepts literal sibling directory arguments and never replaces an existing target. Native Linux filesystems retain renameat2; unsupported filesystems fail with the owned stage preserved.

Final native save/reopen runs inside a newly owned child of the chosen destination stage, so the application itself exercises that volume and directory permissions. Only after the application closes are evidence files copied into private task audits, hash-verified and the exact owned validation child released. The final native copy also retains named descendants, genuine OMML and every table-cell literal; the editable behavior probe moves an owned shape by 1pt, saves/reopens and restores it.
