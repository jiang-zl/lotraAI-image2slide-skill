# Natural parts and shared geometry

For an observed schematic icon with regular structure, choose a compact natural model before tracing pixels. Same-colour windows and radio bands are different parts. A smooth path through noisy colour boundaries can remain swollen or uneven; use source-supported shape families, finite semantic anchors, separate fill/stroke and shared part relations. Scientific curves and measured data never enter this route.

`method{recipe:wireless_vehicle,parameters:{model,pose_degrees,fit:contain,stroke_units:local_pixels}}` supports a source-observed top-view vehicle. `recipe:natural_icon` uses the same source-bound part compiler for other explicitly supported schematic families. The program cannot identify an unknown object for the host: the original-only guide must first establish the subtype, observed parts, source extent/pose and uncertainty. SVG or actual saved PPTX remains available when it preserves those parts better.

`model` has `version:semantic-icons-1`, `family`, `source_evidence`, local `frame:[x,y,w,h]`, `observed_parts:[ids]`, `parts` and optional `relations`. Each part has exactly one `id`, `role`, `source_note`, optional `status`, `geometry` and `style`. Geometry families are `round_rect{bbox,radius}`, `ellipse{bbox}`, `polygon{points}`, `smooth_path{points,corner_indices}`, `elliptical_band{center,radii,thickness,start_degrees,end_degrees,rotation?}` and `line{points}`. Style uses source-supported `fill`, `stroke`, `line_width`; all widths are in the declared mother coordinate units. Round heads/joins are default. One body is one preset/complete path. Do not add unseen wheels, lights or texture.

Every original part must bind exactly one drawing part. Vehicle roles are vehicle_body, front_window, rear_window, side_window, mirror, signal_band and light. A regular signal band uses the analytic band operator; real corners stay explicit. Source-supported inside_body_frame, equal_stroke and concentric_bands relations are compiled before construction. These establish geometric coherence, not a visual-quality score. Other relations continue through the source composition/layout contracts.

Repeat the same immutable `model` for same-family instances. Pose/fit/stroke-unit/container controls do not create another mother cache entry; source-supported structural/style differences create another immutable model. The root stores a mother fingerprint and named part roles. Current recipes.py, semantic_icons.py and semantic_curves.py are cache dependencies. User-edited PPTX remains authoritative and follows existing sync/snapshot rules.

Bind `source_anchor:{part,center:[x,y],source_note}` when the original named body/part centre differs from the whole-group extent centre. The compiler aligns the entire mother to that original part centre, retaining internal proportions. It never registers the candidate to improve evaluation scores; fixed evaluation coordinates stay unchanged. Source anchors are instance placement, not mother cache identity.

The natural compiler poses the mother first and fits its actual native control hull, rather than rotating an empty enclosing rectangle. Source extent is the original painted icon including its signals; an inherited PPT group frame is coordinate metadata and may not enclose that painted ink. Preserve its affine parent mapping during native replacement, but never use it as the source icon-size oracle.

For a source-observed elliptical container, instance parameters may bind `source_container:{kind:ellipse,bbox:[x,y,w,h],margin,source_note}`. The compiler fits the posed native control hull and round-stroke envelope inside the original frame/container by a common scale about its observed centre. It retains all signal parts and refuses a required shrink above 25%, returning the instance plan for correction. No peer, parent coordinate mapping or mother shape changes. Other source boundaries use existing composition contracts; a rectangular extent alone is not ellipse containment.

Review each important part and each critical gap at intended size and one enlarged view: body proportion/regularity, stroke thickness, each observed window, radio colour/width/endpoints, genuine negative spaces, pose and road/container relationships. Original-pixel SSIM/PSNR and edges are auxiliary when removing blur. A continuous Bezier or a correct model manifest is not acceptance evidence. A local finding names owner, part/property, expected/actual and root stage; repair the mother or instance parameters, observe only affected parts/relations and protect satisfactory properties. Keep component frames/text/layout/layers; a defective contour may be rebuilt within its original semantic extent rather than constrained to a fixed subpixel shift.

Store the approved source crop, model, actual saved native PPTX and observed strengths/limitations in the existing local library. Retrieve the compact recipe/model and actual source view, not thousands of historical contour points. Output includes independently reusable native groups; no global model API, font installation or software assumption is added.


## Shipped conditional construction defaults

Fresh observation packets contain `visual_catalog_comparison`: actual previews rendered deterministically from each hash-verified public mother at two poses. Open them and compare original visible anatomy, including small repeated and legend instances. Return `analysis.catalog_review{source_hash,catalog_hash,decisions}`. Each catalog item has one `present`, `absent` or `uncertain` decision with visual evidence. A present decision records matching role counts in `anatomy` and independent `instances[{id,source_roi,source_note,pose_degrees?,purpose?,palette?,source_anchor?,source_container?}]`; each id occurs as a separate component.parts entry under one enclosing owner. Absence is a source interpretation, not a family-name string search; incompatible view/anatomy, identity requirements and explicit style preferences remain valid reasons. Uncertain anatomy returns to original inspection. Do not infer instance counts from rendered nodes or collapse repeated devices into a single quality unit.

The program derives compatible current `source_traits` and recipe methods from those observations, freezes the complete review separately and verifies every instance in fresh construction, cache reuse and final saved-native inventory. The method packet exposes `required_original_catalog_instances`; use their methods as recursive children or named `recipe_instances`. Renaming an observed vehicle as another device later cannot erase its construction requirement. This gallery contains public geometry only; no previous original, accepted drawing, approval message or private task is consulted. Existing imported user artwork keeps its independent original/native preservation path.

The same route applies inside a mixed raw scene. Declare every observed natural assembly as its own semantic child group. The program recognizes declared vehicle body/window/icon classes at leaf level as well as root level; omitting the child group cannot bypass natural construction. `natural_owners.py` checks all method branches and retained caches against actual executable child/instance recipes. Raw natural metadata is rejected. A separately validated saved-native/SVG/quality-trial representation remains available under its existing whole-source quality and editability contracts; it cannot be claimed merely by adding a field to raw objects. Explicit side/perspective models retain their source view; only compatible top-view anatomy selects the shipped top-view mother. `wireless_signal`, `signal_band` and other declared graphic radio contours require geometry, so text parentheses cannot substitute for those shapes. Other natural families and identity photographs retain their own contracts.

Use recursive child methods or add `method.recipe_instances:[{id,source_roi,source_note,parts,method:{recipe,parameters}}]` to the mixed method. The program verifies the current original ROI and model, constructs through the shared recipe cache, replaces only the named group subtree in paint order and preserves its parent. Bind source quality units to the resulting named natural parts. The whole-native gate independently rechecks every recorded part ID, role, count and immediate parent in the saved Scene/native inventory. This rule covers the entire new scene and remains active during scoped replacement; it does not retrieve historical task data or relabel an unknown source as a vehicle.

`config/natural-components.json` registers hash-bound public mother models under `assets/natural-components`. A source-observed top-view vehicle with one vehicle_body, one front_window, one rear_window, two side_window, two mirror and four signal_band roles can use `recipe:wireless_vehicle` with `parameters.source_traits` instead of inventing another mother. Traits contain current source_hash, source_roi, evidence, observed/inferred status, family:top_view_vehicle, those exact role counts, view:top, signal_layout:paired_lateral and purpose:illustrative or decorative. Instance pose/source_anchor/source_container remain source-specific.

The program checks compatibility, validates the shipped asset hash and constructs its eleven natural parts. Explicit source models or an explicit style override take precedence. Different ROIs/poses retain the same geometry mother identity; incompatible anatomy, scientific identity requirements or an unsupported view require a source-supported model. A source-supported per-role palette is allowed. No historical task directory, user approval phrase or previous conversation is consulted. The real package verifier checks catalog resource closure, and clean-install execution must instantiate the mother from the installed public package.
