# Source-bound natural parts and private reusable geometry

Observe the current original before choosing a natural model. Record its visible
parts, source extent, pose, uncertainty, independent fills/strokes and relations.
Use native shapes, paths and finite curves for regular schematic components.
Scientific measurements and unknown anatomy cannot be supplied by familiarity.

`recipe:natural_icon` accepts an explicit current-source model. The retained
typed family aliases also require such a model; no user's previous icon is a
default. A model has version semantic-icons-1, family, source_evidence, local
frame, observed_parts, parts and optional relations. Parts have stable id, role,
source_note, geometry and style. Source-supported round_rect, ellipse, polygon,
smooth_path, elliptical_band and line operators remain available. Current
source evidence determines their coordinates and appearance.

The public component catalog is empty. New users are not asked to inspect a
developer's drawing or a fixed icon gallery. Empty catalogs produce no preview
and require no catalog decision. Each observed current component still needs
its own complete semantic decomposition and native source-bound construction.

Qualified mothers can serve source-confirmed instances within the current task.
Instance pose, placement and external relations stay separate. Local personal
recipes, if deliberately captured/promoted, live in PROJECT/.lotraAI-build/library
and are only proposals for future originals. They never become current source
facts or a stored quality PASS. See knowledge-library.md for the actual manual
capture, promotion and retrieval interfaces and their integration limits.

Keep original/candidate evidence and private model histories on disk. The public
skill package contains generic code/rules and an empty catalog; it must exclude
personal entries, task states, learned models, previews, databases and caches.
