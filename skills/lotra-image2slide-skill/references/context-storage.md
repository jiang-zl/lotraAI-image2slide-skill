# Storage-backed context and resource costs

## Managed reads, recovery and execution scope

`context/index.sqlite` records current-task source identity, selectors, read
purpose, epoch, retained fields, view requests and local cost events. Library
search filters ownership/source metadata before decoding payloads. Private
records belong only to the current task or explicitly verified same-original
lineage. Public reuse needs a promoted source-free constructor with applicability
and validation; current original child/instance checks still cannot be waived.
An unscoped search cannot discover private tasks by a similar name or category.
Legacy records with only an owner name and no original identity remain private
history; they cannot be reused as current evidence until independently rebound.

Model-facing repeated reads may return a smaller retained reference; small
values stay inline when a reference would cost more. Program callers always
receive full data. `--fresh`, another read after the retained notice, or a new
resume epoch restores the body. There is no dependency on the agent detecting
an unavailable platform compaction event. The saved Recovery envelope points
to the exact full state, original, candidate and pending work. Actual hashes
and existing state validators are checked on resume. It is not a new PASS.

Large stable packet fields are emitted once per epoch; later displays retain
their full hash-bound selector. Only the display changes. The original
execution contract, control fields, mandatory views and pending obligations
remain complete. `action_references` select applicable documentation instead
of reading the workflow/history wholesale. No client package contains private
recovery state, user cases, observations or release history.

Every actual native save records object/property changes, actual table cells,
containment and relation dependencies. Changed containers include descendants;
neighbors/connectors/parents join the check closure. Unknown dependencies,
changed source policies or previews choose conservative complete checks. This
graph schedules work, never limits the final original/native/cell reconciliation.
An independent final audit gets a fresh fact scope.

Within one command or registered same-task batch, exact actual native bytes and
decoded images share raw facts; callers receive isolated copies. Numeric cache
hits can skip decoding only when actual file/ROI/code/policy/library identities
match. A changed render falls back to the existing pixel-ROI cache. Semantic
review reuse additionally needs matching actual source/current contextual
crops, peers, parent facts, native signatures, rubric and policy. A repeated
view-file request alone is not a model-observation hit.

Capacity is configured in `config/context-policy.json`. Only recomputable
diagnostic cache rows are evicted by LRU. Decoded-image memory is bounded by
fresh available RAM and policy; oversized inputs are processed without caching,
with identical pixels. Source facts, obligations, best versions and proof files
are preserved. Identical invalid proposals can reuse their specific rejection;
changed evidence and transient host failures remain retryable. An ineffective
strategy is pruned without closing its unresolved task.

Local cost ledgers separate stage/operation elapsed time, characters, bytes,
read skips and view requests. Nested times overlap and must not be added as
exclusive total time. Provider counters include input, cached input, cache
writes, output, reasoning and total when actually supplied; overlapping
subcounters are not summed twice. Missing values remain null. The skill does
not control arbitrary host filesystem reads, history retention or provider
prompt caching; these require capabilities from the host.

The unchanged original, per-unit source contracts, full recursive inventory,
native artifacts, measurements, independent best versions and failures remain
on disk. Bounded display packets are a view of those contracts, not a smaller
execution scope. Programs restore and hash-verify the full packet before
submission. Use `scripts/packet_detail.py TASK PATH SHA [FIELD ...] --owner ID`
or paged `--offset`/`--limit` selectors. Follow `next_offset` or
`next_key_offset` until all required items are addressed; no fixed list cap can
close a parent. Huge strings are losslessly paged, not truncated. Unchanged
references may be retained across compaction; changed files are rejected.

Decoded-pixel-identical enlarged observations reuse a lossless content-addressed
PNG. Source/current roles, source-coordinate windows, parent/neighbor context
and the single fixed display mapping remain explicit. Reuse applies only to
identical evidence, never to another icon that merely looks similar. Original
and actual preview files are hash-verified before deriving any view or metric.

Local raw metrics cache the sampled original/current ROI pixels, registered
sampling rule, complete original identity, implementation/policy and numeric
library versions. An unrelated outside-ROI edit can reuse the diagnostic; an
inside-ROI/source/implementation change cannot. Cache payloads themselves have
checksums. Older unchecked cache rows are historical misses. A retained payload
with new dependencies creates a new library revision. Reused raw SSIM/PSNR do
not certify semantics, native editability or whole-result acceptance. Located
visual review reuse additionally requires identical object versions, source,
rubric, geometry, contextual crop hashes and measurements. Missing versions
are a miss. Global/native-operation receipts are always current and independent.

Before repeated construction, use the existing original-similarity screening
and source-confirmed mother protocol. Reference the mother and numeric instance
pose instead of regenerating primitive geometry in language. Each instance
still has independent original anatomy, source pose, relationships, quality
history and result checks. Source/fitted signal and other curve constructors
use compact parameters and task-local geometry assets. Do not remove small
features or lower texture resolution merely to reduce context or file size.

Every new `build` compacts its newly saved owned PPTX before font embedding and
actual rendering; it preserves the uncompacted input and a replayable resource
receipt. Every saved selected/active candidate is measured automatically by the
task persistence path. `file_cost` gives the exact PPTX hash, compressed and
expanded bytes, media/font costs, native-object/path-command counts, and a
reference to every owner's cost. Large details stay in that report; inspect
named owners only. Resource-cleanup/exact-media opportunities are executed by
the final verified compactor. Complexity flags schedule inspection, not an
automatic quality pass or a forced node/shape limit. Source-confirmed reusable
mothers and bounded curve fitting may improve construction cost; any geometric
simplification needs a frozen source error contract and actual complete result
rechecks. Do not compact or mutate a previously rendered candidate in place.

All official delivery paths use the same complete resource compactor and actual
host equivalence gate for every image. Resource identity includes codec/storage
implementation and policy; construction SVG caches include the codec too.
Relative closed paths, exact eligible PNG palettes, integer cell repartitions
and DEFLATE strategy search complement cleanup/reuse. Inapplicable algorithms
are explicit results, never invisible omissions. Keep original storage if it is
smaller, and preserve native XML/full fonts. See compact-delivery.md for guards.
User outputs are exactly PPTX and the required component table. Temporary PDF
leases survive all dependent HD/font/quality checks and are then released.
Small numerical observations preserve auditability without retaining those
large PDFs. Actual rerendering is required before new disposed-PDF measurements.
Size gains and service token counts remain distinct observations.

`context-usage TASK status --out RESULT` reports context counters separately
from provider token counters. `context-usage TASK record --request REQUEST
--out RESULT` accepts an actual service JSON with a hash-bound task-local
`evidence:{path,sha256}` and explicit `usage_path` (default `['usage']`). It
freezes the evidence, checks numeric consistency, deduplicates provider call IDs
and replays every ledger entry. Missing counters remain null, never zero. Old
`packet_chars` actually measured UTF-8 bytes and are retained as
`legacy_packet_bytes`; new characters and UTF-8 bytes are distinct. No model
call, API key or fabricated service usage is required. Do not infer billable
token savings from entry text, bounded output size, ZIP bytes or cache hits.


## Publication revision 9: clean personal knowledge boundary

Semantic version remains 1.32.0 and component protocol design_revision remains 8.
This source cleanup removes the developer's old component model and mandatory
gallery from public defaults. Fresh installs contain no personal entries, model
assets, task states, previews, database or cache. The default catalog is empty.
Private project libraries and historical task evidence are not distribution data.

Storage-backed context, exact-resource caches and manual local recipe learning
exist. The component-first normal flow does not yet automatically capture and
retrieve cross-task personal recipes. Do not describe that learning loop as fully
integrated or claim measured token savings. Generic operators remain available;
any reused private constructor needs current source applicability and checks.
