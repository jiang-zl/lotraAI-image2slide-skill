# 1.37.4 字体与有限决策设计

目标是让同一份可追溯字体意图产生一致的原生属性，同时保留原图文字、颜色和
强调。普通构造提示、确切身份要求、原图可观察风格、已采用原生绑定分层保存。

1. 原图文字和逻辑颜色/强调区间独立冻结；字体操作不能通过折叠 run 丢弃红字。
2. 每个 run/cell 编译完整三槽计划；写入与预期检查同解析，保存检查仍独立读字节。
3. hint 不定义新策略请求身份；真实源意图修订、确切字体、字重及原文仍使其失效。
4. 源风格、资源可用性、字形样本、族决策、绑定按可见有限步骤推进；成功回执后记账。
5. 同源风格组采用同族；有独立原图差异时可另组，不强制整页或整个 owner 同族。
6. 候选与绑定共用实际字重/斜体/可编辑资格，合成样式必须单独声明和举证。
7. 旧任务显式迁移，留存旧账本与映射；禁止把确切字体要求降为 hint 或抹去历史。
8. source-line 失败有合法决策出口，未知状态诊断停止；真实写入器的未保存输出先与
   冻结源线条交叉检查，再执行保存字节、实际渲染和逐条线最终验收。
9. 独立箭头必须用其保存后的真实顶点、填充/描边/效果限定完整绘制范围；不能把
   shaft 的线宽倍数套给另一 owner 并将远处文字误当箭头。未知绘制属性仍保守检查，
   真实放大/平移/内部空洞/接触差异仍会失败，旧生产器的差异与诊断保留。

沿用已有原生保存日志及 1.37.3 Windows 字体提交恢复，无新通用事务、权限或
常驻 harness。runtime、Math、源 workflow 和证据策略保持独立版本。发布身份、
双平台安装、实际后端、独立正向工作及原图交付分别留证。
