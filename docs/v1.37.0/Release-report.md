# lotraAI Image2Slide 1.37.0

1.37.0 remains a self-contained skill. It makes the registered reconstruction
loop easier to resume and gives its official outputs verifiable completion
criteria. No replacement harness, resident service, account or model key is
introduced. A third-party host with arbitrary code/file access can still ignore
the skill; these are protocol/evidence checks, not hostile-host attestation.

- New tasks use current source/revision/implementation-bound writer grants.
  Product construction and mutations follow the current packet or the existing
  finite action generator. Standalone build requires explicit developer-draft
  mode in private project storage and reports no component/artwork acceptance.
- Original outlines, bounded observation chunks and bounded binding chunks persist
  as immutable checkpoints. Full source/spatial/capability/ownership validators
  seal the complete accumulated data before native construction. This reduces
  request size while retaining whole-source coverage and all final quality gates.
- Packets provide hash-bound submission templates and bounded pending IDs/counts.
  New contexts resume saved work. Explicit prior-bound corrections retain earlier
  snapshots. Source/contract seals commit their checkpoint in the same task-state
  transaction, preventing an interruption from separating the two identities.
- Official export binds the original, complete contract, current independent
  audit, native candidate and final transferred bytes in its private receipt.
  delivery-check and the optional ordinary check_before_finish.py script reject
  intermediates, changed files, empty/incomplete ledgers and stale proofs. The
  caller controls its own reply; no mandatory harness hook is installed.
- An implementation/source/candidate/render-environment change invalidates stale
  ACCEPTED final results in the ordinary next path. Earlier proofs remain in
  history; an old status field cannot substitute for current independent gates.
- SQLite transaction connections close deterministically. Current SKILL.md gives
  one active rule set and progressively links retained source schemas.

Actual Windows PowerPoint and Linux LibreOffice self-authored workflow fixtures
exercise observation through formal two-file export and exact-byte verification.
Negative checks cover bypasses, current-packet/phase restrictions, coverage,
retained corrections, 40 components/200 feature bindings, final-file/receipt
tampering, incomplete ledgers and repeat export. Detailed current counts and
byte-bound results are in Workflow-checks.json, Installation-checks.json,
Backend-and-delivery-checks.json, Final-distribution-checks.json and
Version-consistency.json. These fixtures do not accept external user artwork.
WPS and physical macOS require their own host evidence and remain unqualified.

Product/core/packager/installer/documentation use 1.37.0. Execution policy is
workflow-execution-1.37.0; source workflow 1.35.2, source-features/spatial 1.35.1,
design_revision 8, native Math policy 1.35.3 and runtime/companion 1.14.0 remain
independently versioned. Unchanged runtime executable/resource bytes and immutable
bundle parts are reused. Online installation updates only changed managed files;
source and runtime metadata channels/entries are synchronized incrementally.

Both repositories use dev and numeric 1.37.0 branches, with formal source tag
v1.37.0. Preserve 1.35.4/1.35.5/1.36.0 tags/assets, user originals/deliverables,
private tasks/fonts/knowledge, existing local modifications and global skills.
The active custom local skill is not forcibly updated or relabeled by publication.
