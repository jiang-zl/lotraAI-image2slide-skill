# 1.37.0 static and behavioral review

The existing acceptance engine remains authoritative. New execution guards are
task/phase scoped; source and binding staging cannot construct native output or
mint PASS. All source/spatial/native capability validators still run in complete
form at seals. Seal checkpoint refs are part of the same indexed task commit.
Immutable snapshots support restart and explicit prior-bound corrections.

Formal acceptance requires nonempty exact component coverage, current saved
native/render evidence, complete layout/fonts and independent original-to-output
review. Stale accepted final reports are invalidated by next/refresh and retained
as history. The separate delivery checker cannot create acceptance and checks the
registered private proof plus exact final artifact bytes. Developer drafts have
explicit private scope and unverified metadata/status. A local writable host can
modify code/evidence; no cryptographic trust claim is made.

Current entry instructions supersede the historical layered entry prose. Detailed
retained contracts are loaded only for relevant packets. The product remains a
skill, without mandatory harness hooks, replacement agents, remote services or
extra model providers. Existing prepared runtime binaries are reused.

Validation includes positive real-host workflow/export, current negative protocol
and final-artifact cases, current Windows/Linux differential/install/distribution
checks and public identities. Physical WPS/macOS and external-artwork acceptance
remain distinct and unqualified by these fixtures. User modifications/data and
historical releases are protected.
