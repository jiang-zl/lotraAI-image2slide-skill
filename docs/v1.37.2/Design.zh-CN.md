# lotraAI 1.37.2：连接线证据与自适应检查设计

本次以公开发布的 1.37.1 为基线。核心原则是：完整义务不减少，检查方法按
当前证据是否充分来选择。程序不读取模型身份，也不采信模型自报的智力或置信度。
较强模型能更快给出准确源观察、合适构造和清楚复核，因而减少疑点与修复；
较弱模型仍受同一套可执行门禁约束。视觉通过可以结束可选深入检查，但不能
取消必须执行的原生几何、当前渲染、覆盖与交付检查。

## 1. 在构造前冻结原图事实

每条线记录原图坐标系中的有序线段或曲段、起终点、各段方向、转角位置及
方向、曲线控制事实、标记锚点与类型、实心或空心、大小区间、线宽/颜色/透明度、
端帽/接头/复合线与虚线间距、实际接触或留隙、端口目标、分叉/交叉/共享线段、
原图确认的遮挡及依据。无标记也必须明确确认。原图事实独立于 Scene 和输出。
绑定程序编译六项不可缩减义务：route、terminals、markers、stroke、topology、
visibility，并核对所有原生线对象归属。不能漏掉短臂，也不能把意外交叉当分叉。

直线、斜线、一般折线、正交折线、二次/三次曲线、弧线、闭合路径、实心自由
轮廓箭头和单端/双端/无标记都有明确表示。实线、虚线、点线、点划/自定义间距、
复合线分别检查。未具备有效提取器的预设、特效及复杂曲线遍历保持待决。
尤其是自交曲线回路换序，不能靠相同集合、总长或共享交点投影判通过。

## 2. 程序检查保存结果与真实渲染

独立解码器读取保存的 DrawingML、祖先变换、实际路径、连接目标和有效样式；
不调用构造器来生成预期答案。折线逐角对应并比较有符号方向，路径作双向距离、
长度和顺序检查，两端分别比较位置、切线、标记与接触。原生包中的未知额外线
不能躲过对象清点。遮挡必须由原图声明且有实际后绘制的不透明遮挡对象。

实际渲染必须绑定当前 PPTX、预览、后端和源图。按线、按段检查颜色支持、源
线身像素覆盖、对应法向线宽/复合线条带、虚线相位及完整间距、两端标记的完整
双向绘制距离。坐标固定在同一原图画布，禁止对候选作最佳对齐。不能用整个
面板的暗像素总量或长线峰值来证明某条短折线正确。

## 3. 用充分性控制开销

普通方法提供有效且在界内的结果时，停止该项可选细化；只为不确定项启用
有限的局部精细方法。有效失败直接保留，不能换算法或放宽容差把它消掉。
不同问题的证据不能互相抵消：原生通过不等于外观通过，视觉印象也不能豁免
有效程序失败。像素或曲线近似误差必须显式进入界限，无法测清保持 INVALID。

标记普通界限不确定时，可对同一组固定前景像素单元并集计算更紧的有界距离，
覆盖完整内部与边界；不虚构亚像素真值、不缩放源图、不改变颜色口径。只有
更高实际渲染分辨率可能解决问题时，才请求有限次重渲染，并保留旧证据。
原图精度本身不足时返回源事实决策。预算耗尽从不产生 PASS。

程序按当前依赖批量共享原始图片/原生解码事实，通用指标仅计算冻结需求中
声明的生产器，清楚视图可同时覆盖六个准则。独立最终门禁重新检查当前字节，
不复用历史数值 PASS。调用次数反例已验证普通充分情形不运行 deep；本次没有
测量模型 token、外部 harness 或普遍耗时收益，因此不宣称节省比例。

本版发布期回归和跨渲染器预设校准不属于每次重建任务的运行步骤。用户任务
只执行当前源图/对象适用的必查项；局部修复只使真实受影响的依赖失效，完整
视觉复核仍在组件、布局和一次字体复核完成后进行，避免每改一笔就重做整页。

## 4. 逐线视觉与疑点闭环

每条线有当前原图/实渲染 crop、ROI、倍率、文件哈希和测量引用。观察者实际
查看整图及全部逐线视图，明确六项 PASS/FAIL/UNRESOLVED；程序不填语义 PASS。
清楚情形共用可读 crop，必要的小细节与疑点放大；长线/曲线疑点完整分片，
不能仅看两端。自由文字及预期 Scene 不能替代当前像素观察。

程序疑点在发出复核包时立即留账；观察者的 FAIL 或 UNRESOLVED 即使没有
额外问题文字，也会创建疑点。刷新图、修改实现或后续测量通过不会自动删除。
关闭必须引用当前对应放大证据、明确的解决说明、同项有效程序 PASS 和视觉
PASS。有效 FAIL 进入有限原生修复，UNRESOLVED 先取得证据。旧清单失效返回
当前复核入口，保留历史，不把旧接受结果当成当前结论。

原生修复及构造计划重绑必须继承疑点账本和已经消耗的渲染细化次数。旧疑点
即便曾经 RESOLVED，只要源图、保存原生、实渲染或实现的绑定发生变化，就
重新成为 OPEN，并保留 prior_resolutions。复核准备和独立验证两处执行这个
规则；不能靠换清单、重新绑定或把线清点改为空来逃掉原有问题。

| 当前状态 | 程序允许的下一步 | 放行条件 |
|---|---|---|
| 六项均有效 PASS，视觉清楚且无疑点 | 结束可选深查，进入最终审计 | 当前逐线引用、整体复核和全部最终门禁通过 |
| 普通方法 INVALID，可由更紧误差界解决 | 仅细化对应线和准则 | 同一事实/口径/阈值下得到有效结论 |
| 实渲染精度不足且提高精度有意义 | 保留旧证据，有限次实际重渲染 | 原生及后端不变，新证据重新复核 |
| 有效程序 FAIL 或明确视觉 FAIL | 按当前授权做有限局部原生修复 | 重新保存、渲染、测量并消解所有受影响疑点 |
| 视觉 UNRESOLVED 或证据冲突 | 生成定位放大证据并保留问题 | 同项有效程序 PASS、当前放大引用和明确视觉 PASS |
| 原图不清、提取器不支持或有限预算耗尽 | 保留待决，返回源事实/表示/宿主决策 | 取得新的有效依据；不能自动变成 PASS |
| 缺项、陈旧引用、错误附件或缺少最终门禁 | 拒绝放行，返回对应阶段 | 补全并重新验证当前字节 |

## 5. 最终放行与验证边界

所有源线与原生线清点一致、六项全部有效通过、所有疑点关闭、当前整体视觉
与完整最终门禁通过后，才能正式导出；无连接线情形仍必须正向证明清点为空。
交付再核对正式回执与实际附件字节，缺失门禁、陈旧接受、漏项、变更文件或
错误附件均不能放行。重做验收后用新目录导出，既有交付保留。

专项反例涵盖同起终点/包围框/总长而拐弯相反、短臂缺失、箭头反向、切线、
祖先变换、曲线/弧线/闭合/实心箭头、虚线/复合线、目标/拓扑、填充内部缺口、
未知/无效度量、缺失或陈旧 crop、疑点遗失、失效后的恢复、交付门禁及方法选择。
独立前向测试只从自有原图开始，真实发现并修复正常调用链问题，再完成当前
放大复核、最终审计和正式交付。最终安装载荷在 Windows PowerPoint 与原生
Linux/WSL LibreOffice 分别做完整回归，独立首次观察与安装后重放分别记录。

跨后端校准保留真实差异：24 个冻结折线预设组合在 PowerPoint 全部符合，
LibreOffice 有 10 个符合、14 个发生明显走向差异。后 14 个全部被当前生产
逐线渲染门禁的有效失败拒绝，没有记为预设兼容 PASS。保持同一原图和 2.5
source_px 校准上限，用现有可编辑原生显式路径表示相同 24 条线，在两个后端
逐项通过。原预设文件、原失败渲染与失败报告均保留。该结果说明必须验证
实际后端，不能由 DrawingML 解码正确推断绘制正确；修复应在现有授权流程内
采用适合当前后端的原生表示，而不是改写源路径或放宽阈值。此校准不替代每项
用户任务的六准则检查、语义复核和完整交付验收，也不承诺路径自动重新路由。

精确结果、数量、实现与附件哈希以本版 Validation-summary.json、
Line-evidence-checks.json、Workflow-checks.json 和 Installation-checks.json 为准。
这套协作协议可以强制覆盖、身份和程序谓词，哈希不能证明观察者确实看过图，
也不提供抵抗恶意本地宿主的隔离。本次不验收已经丢失的错误结果、用户管理
架构照片、所有外部复杂图、物理 WPS/macOS 或任意第三方 harness。
