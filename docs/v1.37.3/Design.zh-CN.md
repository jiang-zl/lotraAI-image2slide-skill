# 1.37.3 字体链路修复设计

字体修改的源授权、候选绑定和已保存原生文件分别保留自己的身份。当前
packet 给出精确 owner、run／单元格位置、脚本、原字体与 prior_binding_hash。
整组件替换授权覆盖其字体；单纯 text_body 写入不扩大成字体授权。原始字段
授权经过原生写入投影时保留，用户字体锁始终有效。缺少授权的候选可以携带
当前原图证据返回源决策，并保留未执行计划，避免反复提交同一无解候选。

字体绑定批次先在副本中验证。候选字体不会提前改写活动绑定，只有现有原生
保存日志提交成功后，才一并采用字体账本。失败批次不保留前半批更新。

Windows 的已打开外部文件句柄仍会阻止原子替换。直嵌和 provider 路径共用
受身份约束的暂存提交记录：目标、输入哈希、候选字体身份、结果哈希及阶段
明确对应；所有 ZIP 句柄关闭后再替换。遇到共享锁时保留已验证暂存和原文件，
解锁后继续同一提交和已保存构建，不重新生成形状、不消耗另一次原生构建。
完成替换后发生中断也可继续；未知残留、字节变化与预算冲突必须停留为冲突。
提交恢复次数有上限。这是现有保存日志的定向修复，没有另建通用事务框架。

保存后的字体门禁以 owner、位置、脚本逐个解析真实 run／单元格，同时核对
文字内容、字体槽位与完整覆盖。多 run 交换字体、增加未绑定文字、改动文字、
混合中英文、换行、表格及 Office Math 均有针对性回归。

独立修复测试还暴露了受管读取的依赖交付缺口：已获准父资源返回了当前
Scene 或测量文件的引用，却没有同时交付这些子资源的读取凭据。现在仅为
本次选择结果中实际返回、同任务同原图且哈希相符的子文件发放凭据；分页
之外的兄弟资源、变化的文件和越出任务的路径继续拒绝。缓存重放也执行同样
的身份核对。五项回归覆盖该边界，原生构建与验收规则、质量阈值保持不变。

产品版本为 1.37.3；workflow 1.35.2、design_revision 8、execution 1.37.0、
evidence-checks 1.37.2、Math 1.35.3、runtime／companion 1.14.0 保持独立。
原图、用户任务、私有字体／知识、全局技能和已修改的活动 1.35.3 安装保留。
源代码修复、环境安装、真实后端行为与外部原图验收分别记录。
